# Frigate full-input per-locale A/B

The public PR813 build completed all 33 original supported locales with normal Vite optimization. The first matched actual Live-route pair shows no improvement: compiled output requested more bytes and substantially more JS resources. Timing values below are one-pair diagnostics, not a repeated performance qualification.

Observed encoded response-body totals, including document and all completed ResourceTiming entries begun before readiness, are 1,434,635 → 1,524,706 B desktop (+6.28%) and 1,212,165 → 1,299,844 B mobile (+7.23%). Normalized Q4 totals compress every text response body, including identical mocked API JSON, and retain binary bodies unchanged. All HTTP requests begun before readiness were awaited through completion; none had unavailable bodies. These are whole initial-page totals, not i18n-only estimates. Original identical Frigate E2E API/media/WebSocket fixtures supply synthetic cameras and transparent image media; actual camera streaming is not measured.

Both arms rendered `Front Door - Direct - Frigate` with `html.lang=fr`, naturally visible French accessibility labels `Retour` and `Afficher les vidéos archivées`, zero strict browser/request errors, and no interactions before readiness. Desktop also rendered visible `Retour` and `Historique` text. Mobile naturally uses icon-only controls, so its readiness gate uses the same French accessibility labels and route title; it does not invent visible text. Native/compiled screenshots match byte-for-byte for each viewport. The original five-second title assertion was too short for the throttled cold mobile route; that failed capture is excluded, and the passing capture allows up to 60 seconds of natural polling without a fixed delay.

The original Frigate source is `ff9eb8f18430198548d9c9d2cf138ed9ac7b526b`. Original catalogs contain 33 supported locales, 29 physical namespaces (28 configured at initialization plus `views/setup`), 5,348 normalized union IDs, and 128,025 physical translated strings. The earlier 3,039-ID prototype covered only nine namespaces and is not a full-app input comparison. No keys/locales were manually trimmed.

The candidate retains i18next/react-i18next semantics and loads selected strings from compiled message functions through static-import namespace facades. Facades preserve exact sparse original key shape and nesting. Original English/regional parent fallback catalogs remain separate lazy JSON imports, preserving normal plural/context/object fallback behavior. Exact compiled resources match all 957 original sparse namespace trees. Literal transport checks all 128,025 strings; physical export inventory confirms all 5,348 expected message exports. All 33 public locale variants are present, and no unreplaced compiler static marker remains in 53,130 client JS files.

The optimized native control chooses the original stored/system language before initializing lazy `objects`/`audio` namespaces. Its language hierarchy is extracted from the original LanguageProvider into a shared helper. This baseline optimization is not counted as a compiler benefit. Both builds use identical original app dependency locks, ES2022 target, original `keepNames` configuration, and default optimization; no manual chunk map or special bundler mode was added.

Compiler source is public commit `490a5c0d0c4c44b93f61ad494b28f74987e5f245`; the app uses `createBuilder().buildApp()`, `experimentalPerLocaleBuild: true`, and `outputStructure: "message-modules"`. Actual host is Node 22.23.2 / Vite 8.3.3 / Rolldown 1.2.13. The plugin manifest records Vite 8.1.4 / Rolldown 1.1.5 from the compiler dependency tree; those manifest fields are distinguished from actual host versions in the provenance. All 490 installed @inlang/sdk 4.0.0 files and all 95 @lix-js/sdk 0.19.0 files match exact stock npm tarballs. No SDK/timer/row guard was changed. One explicitly paused ingestion attempt crossed a stock open timer and is excluded from clean failure evidence; the uninterrupted full build passed.

The preliminary HTML+Live static closure is 1,090,525 → 1,092,181 B Q4 (+0.15%); it omits lazy namespace/font/media/API requests and understates the actual initial graph. The current adapter exposes one dynamic namespace facade per physical locale, and normal Rolldown shares message chunks across these entries. This increases the actual request fan-out. A reviewable alternative with one lazy namespace module and automatically generated sparse locale branches is prepared separately in `prepare-single-namespace.py`; it has not been built or measured. Neither the first adapter's timing regression nor an untested refinement establishes a general performance claim for every migration.
