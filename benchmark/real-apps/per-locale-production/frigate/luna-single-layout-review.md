# Single-namespace candidate: read-only review

Reviewed the first generated single-namespace adapter and Vite configuration statically. I did not build or open a browser, and I did not run the parity script.

## Findings

- The adapter reconstructs each locale's original sparse JSON shape. The generator walks the locale JSON, stores the original path segments, and emits only that locale's string leaves into its branch ([prepare-single-namespace.py](prepare-single-namespace.py#L5), [module generation](prepare-single-namespace.py#L12)). A read-only structural scan of the source locale files found 128,025 string leaves, no missing message IDs, and no non-string leaves. Missing locale/namespace files become empty resources, leaving fallback handling to i18next.
- Dotted source keys are retained in the output path while their message-ID lookup splits dots to match metadata paths. The scan found 90 dotted-key occurrences and no normalized metadata-ID collisions. I found no `originalkeys` property in the locale JSON; if “original keys” means the source keys and nesting, those are preserved by the `path` arrays. The generated resource tree remains in the same form as the input JSON, including plural/context suffix keys.
- The i18next setup retains `fallbackLng: "en"`, `keySeparator: "."`, React `Trans` configuration, and the rest of the existing engine configuration ([candidate-single-i18n.ts](candidate-single-i18n.ts#L31)). The backend dynamically loads the requested namespace and returns that module's resource object ([candidate-single-i18n.ts](candidate-single-i18n.ts#L3)). `useTranslation` and `Trans` therefore keep using i18next's namespace, plural, context, and key lookup behavior. This is a source-level assessment, not a runtime parity result.
- The existing fallback table is copied unchanged from the previous compiled loader ([prepare-single-namespace.py](prepare-single-namespace.py#L22)). In the `pt-BR` branch it provides `pt` and `en` JSON loaders; i18next's default language hierarchy should try `pt-BR`, then `pt`, then configured English fallback. Other translated locales have English fallback loaders. This preserves sparse regional resources instead of filling their missing keys during generation.
- The loader map has one dynamic import per namespace (29 total), with no route-specific trimming ([prepare-single-namespace.py](prepare-single-namespace.py#L23)). This should avoid fetching unrelated namespaces when i18next only requests a subset. The granularity is the whole namespace: every message ID assigned to a requested namespace is imported by that namespace module.
- Static locale folding is wired consistently in source. Each Vite locale environment defines `globalThis.__PARAGLIDE_STATIC_LOCALE__` to one literal locale and writes to its locale output directory ([Vite locale plan](../../paraglide-locale-namespaces-main/src/bundler-plugins/per-locale-build/vite-environments.ts#L55), [environment definition](../../paraglide-locale-namespaces-main/src/bundler-plugins/per-locale-build/vite-environments.ts#L175)). The generated module's `rows` expression branches on `experimentalStaticLocale` ([prepare-single-namespace.py](prepare-single-namespace.py#L14)). Rolldown should remove the other locale branches and unused locale message bodies after the define is applied, but the emitted chunks were not inspected, so cross-locale tree-shaking and fan-out reduction remain unproven here.

## Integration limitation

Frigate's existing language picker stores the selected language and reloads the current URL ([language-provider.tsx](/root/repos-iii/frigate-per-locale-ab/web/src/context/language-provider.tsx#L30)). In a specialized bundle, `getLocale()` returns the compile-time locale before consulting browser strategies ([runtime.js](/root/repos-iii/frigate-per-locale-ab/web/src/paraglide/runtime.js#L292)); the plugin emits locale variants under `__paraglide/<locale>` ([vite-environments.ts](/root/repos-iii/paraglide-locale-namespaces-main/src/bundler-plugins/per-locale-build/vite-environments.ts#L64)). Thus localStorage plus reloading the same URL cannot select another compiled locale. The application or deployment must navigate to the corresponding locale entry for the existing picker to remain effective. The reviewed adapter does not supply that navigation wiring.

## Limits of this review

I did not verify the generated bundle's dynamic-entry count, chunk bytes, tree-shaken locale contents, or browser behavior. The static marker and namespace graph make the intended result plausible, but only the active build can establish whether Rolldown actually removes the other 32 branches and avoids cross-locale fan-out. No claim of complete runtime parity is made.
