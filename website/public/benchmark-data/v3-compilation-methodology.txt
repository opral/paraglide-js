Paraglide JS v3 compilation benchmark, measured November 2, 2026

Baseline: npm @inlang/paraglide-js 2.29.3, unmodified distribution.
Candidate: main 2a01eb31001375cd4d1ae26a41a265df32c8340b, unreleased v3.
Variants: v2 message-modules; v3 message-modules; v3 virtual-modules via Vite.
Same dependencies: SDK4.1.0, plugin-message-format4.5.6, Vite8.1.4,
TypeScript7.0.2 (including native v2 declaration emission).
Host: Node24.22.1, Apple M5 Pro,64GiB RAM, macOS arm64, local APFS.
Sequential workers, shared development host, OS filesystem caches not flushed.

Six deterministic synthetic catalogs:1000/20000/50000 keys x2/10locales.
Message mix:50%static,35%interpolation,10%plurals,3%currency,2%dates.
Same small plain-Vite application uses200messages with static m.key()calls.
These are controlled fixtures, not customer apps or full framework builds.
Every variant emits declarations; messageModuleSize1; cookie/baseLocale strategy.
Three balanced rounds, each a fresh process/outdir/compiler cache.108process
trials total (6fixtures x3variants x2modes x3rounds). Extra fourth-round samples
were excluded as an incomplete round before reporting. No significance claim.

Full compilation: actual compiler plugin buildStart from project/config loading
through JS+DTS publication and compiler cache bookkeeping. Excludes importing
Vite/compiler modules. Virtual output is measured through its Vite integration.
Incremental: file write + actual watchChange hook completion; one translation
edit, one input edit, one added message. Serialization and output-validation
module invalidation outside timing. Watcher/debounce disabled for delivery.
Vite startup: before importing Vite/compiler through first completed HTTP SSR
response. Includes initial compilation. No readiness probe warms the graph.
Static accesses can be rewritten to direct message imports; dynamic namespace
access can retain the full graph and need not show the same startup gains.
Production: entire client Vite build, including compilation/bundling/minifying/
writing. JS gziplevel9/Brotliquality11; summed JSasset bytes only. Not a full
SvelteKit/TanStack/Next.js SSR build, and not DOM readiness or browser LCP.
Typecheck: strict TypeScript7.0.2, skipLibCheckfalse, noEmit, Bundler resolution,
types:[],200usedmessage consumers plus required-error checks. Three fresh tsc
processes per build trial, median first within trial, then across three rounds.

Correctness:200expectedstrings in every locale; initialSSR and executed-client
HTML hashes match across layouts/versions. Edits and added declarations checked.
Strict consumers accept valid calls and reject missing inputs. Bundles retain
exactly200used message markers and no unused markers.

Tables report medians; JSON includes observed min/max. Large-project headline
is the geometric mean of four per-fixture median ratios (20k/50k x2/10locales).
Physical7.0423x=85.8002%less elapsed time; virtual19.0507x=94.7509%less.
No causal attribution of total speedup to one optimization.
